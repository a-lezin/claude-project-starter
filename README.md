# Claude Project Starter

[English version](README.en.md)

Чистий стартовий проєкт для роботи з Claude Code без програмування. Усередині: база знань, яку веде сам Claude (LLM Wiki), онбординг, захист файлів і приклад підключення MCP. Склонуйте проєкт, запустіть `/onboarding` і працюйте над своїм продуктом.

## Ідея: LLM Wiki

Ви кладете джерела і ставите питання. Claude пише сторінки бази знань, зв'язує їх посиланнями і тримає зміст актуальним. Знання накопичуються: нове джерело оновлює вже наявні сторінки. Підхід описав Andrej Karpathy: [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f).

| Тека або файл | Чиє | Що там |
|---|---|---|
| `raw/` | ваше | Джерела: документи, звіти, експорти. Claude лише читає |
| `wiki/` | Claude | Сторінки бази знань, `index.md` (зміст), `log.md` (журнал) |
| `CLAUDE.md` | спільне | Правила: як Claude читає, пише і перевіряє wiki |
| `artifacts/` | для людей | One-pager, дашборд, звіт. Збираються з wiki |

## Що всередині

```
CLAUDE.md              правила роботи Claude в цьому проєкті (англійською)
AGENTS.md              те саме для Codex та інших агентів: відсилає до CLAUDE.md
raw/                   ваші джерела, лише для читання
wiki/                  база знань: index.md, log.md, сторінки
artifacts/             результати для людей
examples/              заповнений приклад (застосунок Spokly); теку можна видалити
.claude/
  settings.json        дозволи і хуки
  hooks/               3 скрипти захисту
  skills/onboarding/   скіл першого запуску
  agents/              агент context-sorter: розкладає джерела по wiki
.mcp.json              MCP-сервери проєкту (приклад: база законів України)
.gitignore             що не потрапляє в git: секрети, відео, архіви
.env.example           шаблон для ключів
```

## Що потрібно

- [Claude Code](https://code.claude.com/docs/en/overview).
- Git. На Windows потрібен [Git for Windows](https://git-scm.com/download/win): без нього хуки не запускаються і блокують усі дії.
- [GitHub CLI](https://cli.github.com/) (`gh`), якщо ви зберігаєте проєкт на GitHub.

## Старт

### 1. Скопіюйте проєкт

Відкрийте Claude Code у теці, де тримаєте проєкти, і напишіть:

```text
Склонуй https://github.com/a-lezin/claude-project-starter у папку my-project і від'єднай копію від оригінального репозиторію. Потім створи на моєму GitHub приватний репозиторій my-project і опублікуй туди проєкт. Спершу покажи список файлів і дочекайся мого OK.
```

Те саме руками:

```bash
git clone https://github.com/a-lezin/claude-project-starter.git my-project
cd my-project
git remote remove origin
gh repo create my-project --private --source=. --push
```

Інший шлях: кнопка **Use this template** на сторінці репозиторію.

> ⚠️ Ваш репозиторій має бути **приватним**: у `raw/` і `wiki/` лежатиме робочий контекст.

### 2. Відкрийте проєкт у Claude Code

Запустіть `claude` у теці `my-project`.

- Підтвердьте довіру до теки. Без цього хуки не працюють.
- Claude Code спитає про MCP-сервер `sviy-laws` з `.mcp.json`. Дозвольте його, якщо вам потрібна база законів.

### 3. Пройдіть онбординг

```text
/onboarding
```

За 10–15 хвилин Claude:

1. Поставить 6 питань про продукт, вашу роль, цілі, конкурентів і зручний формат відповідей.
2. Спитає, якими AI-інструментами ви вже користуєтесь і де лежить ваша інформація.
3. Допоможе перенести контекст: дасть промпт для експорту з ChatGPT, Gemini чи claude.ai і попросить покласти файли в `raw/`.
4. Покаже тези, список сторінок і зміни до `CLAUDE.md`. Прочитайте їх і скажіть «OK».
5. Запише сторінки у `wiki/`.

Немає свого продукту? Скопіюйте два файли з `examples/raw/` у `raw/` і запустіть `/onboarding` на них.

## Щоденна робота

| Що | Коли | Промпт |
|---|---|---|
| **Питання** (query) | будь-коли | `Яка наша основна аудиторія?` |
| **Нове джерело** (ingest) | ви поклали файл у `raw/` | `ingest raw/zvit-zhovten.pdf` |
| **Зберегти відповідь** | Claude дав добру відповідь | `Збережи цю відповідь у wiki як сторінку` |
| **Перевірка** (lint) | щотижня | `lint` |

Claude спершу показує тези і чекає вашого OK, потім пише у wiki. Якщо відповіді у wiki немає, він каже це прямо.

Читати wiki зручно в [Obsidian](https://obsidian.md): відкрийте теку `wiki/` як vault і подивіться Graph view.

## Захист

Проєкт має чотири запобіжники. Налаштовувати їх не треба.

| Запобіжник | Що робить |
|---|---|
| Дозволи в `.claude/settings.json` | Забороняють Claude змінювати `raw/` і читати `.env`, ключі та теку `secrets/` |
| Хук `protect-files.sh` | Друга лінія для тих самих заборон: вона працює, навіть якщо правило дозволів хтось прибрав |
| Хук `block-dangerous.sh` | Блокує небезпечні команди: `rm -rf` на `/`, `~`, `..`, `.git`; `git push --force`; `git reset --hard`; `git clean -f`; `chmod 777`; зміни в `raw/` через термінал; показ і відправку секретів |
| Хук `check-large-files.sh` | Перед `git add` і `git commit` зупиняє файли понад 10 MB |

Чого захист **не** закриває:

- Це запобіжник, а не пісочниця. Скрипт на Python чи Node або команда `bash -c '…'` можуть його обійти.
- Обмеження діють лише на Claude. Finder, Obsidian і git у вашому терміналі працюють як завжди.
- Секрети розпізнаються за назвою файлу. Ключ, вставлений у чат, не захищений: тримайте ключі лише в `.env`.
- Режим Bypass permissions вимикає підтвердження дій. Не вмикайте його.

Якщо хук зламався і блокує все, запустіть `claude --settings '{"disableAllHooks": true}'` і попросіть Claude відновити теку `.claude/hooks/` з git.

## MCP: сервіси на рівні проєкту

Файл `.mcp.json` підключає MCP-сервери для всіх, хто працює з цим проєктом. Це окремий механізм, не конектори claude.ai.

Приклад у файлі: `sviy-laws`, довідкова база законодавства України.

1. У Claude Code введіть `/mcp`, оберіть `sviy-laws` і увійдіть через Google.
2. Спитайте: `Знайди в Кодексі законів про працю норму про тривалість щорічної відпустки`.

Якщо ви вже маєте такий самий конектор у claude.ai, інструменти з'являться двічі. Тоді приберіть сервер з `.mcp.json`.

Додати свій сервер:

```bash
claude mcp add --transport http <назва> <url> --scope project
```

Не кладіть токени у `.mcp.json`: цей файл потрапляє в git. Додавайте лише сервери, яким довіряєте.

## Скіл і агент

- **Скіл `onboarding`** (`.claude/skills/onboarding/`): інструкція першого запуску. Викликається через `/onboarding` або словами «збери контекст». Запустіть його знову, коли хочете додати контекст з іншої LLM чи нові джерела.
- **Агент `context-sorter`** (`.claude/agents/context-sorter.md`): окремий виконавець зі своїм контекстом. Він читає одне джерело і повертає розкладку: правила, факти за сторінками, відкриті питання. Claude запускає по агенту на кожен файл, паралельно. Агент нічого не пише.

Це також зразки для ваших власних скілів і агентів:

```text
/skill-creator створи скіл локально в цьому проєкті: [що він робить і коли]
Створи в проєкті агента, який [що робить]. Дані читає з: [звідки], лише читання.
```

## Git

- `.gitignore` не пускає в git секрети (`.env`, ключі), відео, аудіо, архіви, згенеровані PDF в `artifacts/` і налаштування Obsidian.
- Картинки (`png`, `jpg`) у git потрапляють: їх вбудовують one-pager-и.
- Файли понад 10 MB тримайте на Google Drive або додайте в `.gitignore`.
- Git-команди вчити не треба. Пишіть словами: `Збережи і опублікуй зміни`, `Забери зміни колег`.

## Інше

- **Codex та інші агенти** читають `AGENTS.md`, який відсилає до `CLAUDE.md`.
- **Плани** з Plan mode зберігаються в теці `plans/`.
- **`examples/`** містить заповнений приклад. Видаліть теку, коли вона стане непотрібною.
- **`CLAUDE.md`** ваш: змінюйте правила під себе. Тримайте файл коротким і без фактів про продукт.
